## Design Context

### Users
Primary audience: hiring managers and technical recruiters evaluating distributed systems / backend engineering skills. They spend seconds scanning before deciding to dig deeper. The UI must communicate competence instantly — clean, purposeful, nothing wasted. Secondary audience: engineers who will appreciate architectural depth visible through UI structure (status pipelines, job states, search results).

### Brand Personality
**Three words:** Precise. Capable. Restrained.

Tone is confident without being flashy. This is a tool built by someone who knows what they're doing — the UI should feel like it was made by a senior engineer who also cares about craft. No decorative chrome, no marketing copy energy.

### Aesthetic Direction
**Visual tone:** Dark, technical, high-contrast. Think Vercel dashboard — muted zinc/slate backgrounds, sharp white text, minimal borders, monospace accents for IDs / statuses / metadata.

**References:** Vercel dashboard (primary). Linear (density, keyboard feel). Raycast (precision).

**Anti-references:** Purple gradients, nested rounded cards, Inter + pastel color palettes, anything that reads as "AI generated SaaS template".

**Theme:** Dark mode only. No light mode toggle.

**Typography:** Geist Sans for UI, Geist Mono for code/IDs/status values/timestamps. Already in layout.tsx — lean into it.

**Color palette:** Near-black background (`zinc-950` / `#09090b`), zinc scale for surfaces, white for primary text, zinc-400 for secondary. One accent color max — a desaturated blue (`sky-500` / `#0ea5e9`) for interactive states and progress indicators. Red for errors, emerald for success — both desaturated.

**Spacing:** Tight. This is a dashboard, not a landing page. Dense information layout with deliberate breathing room, not generous padding everywhere.

### Design Principles
1. **Information density over whitespace** — every pixel earns its place. Show more, scroll less.
2. **Status is the hero** — video pipeline state (queued → processing → complete → failed) should be legible at a glance from the list view.
3. **Monospace for machine data** — IDs, durations, resolutions, timestamps always in Geist Mono. Reinforces the technical identity.
4. **No decorative chrome** — borders, shadows, and rounded corners only where they carry semantic meaning. Prefer separator lines over cards.
5. **Confidence without noise** — no loading skeletons for data that loads fast, no toast stacks, no modal-within-modal flows. Actions are direct.
